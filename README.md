> A reproducible PyTorch laboratory for evaluating Chinese two-stage retrieval strategies used by evidence-aware research assistants.

`chinese-evidence-retrieval-lab` is the experimental companion to [CountyResearchAI](https://github.com/OrdoAbChao7/CountyResearchAI). It evaluates whether retrieval and re-ranking strategies improve **passage relevance** on a public Chinese ranking benchmark before any strategy is integrated into an upstream research assistant.

**It does not claim to validate the factual correctness of county research reports, nor does it send private CountyResearchAI data to third-party services.** The experiments are designed around public benchmark data, fixed train/dev splits, versioned manifests, and repeatable metrics.

## Research question

Given a Chinese query and a passage corpus, does a two-stage system—dense retrieval followed by Cross-Encoder reranking—improve ranking quality over lexical and pretrained dense-retrieval baselines?

The primary study uses [T2Ranking](https://github.com/THUIR/T2Ranking), a public Apache-2.0 Chinese passage-ranking benchmark with official train/dev query splits and retrieval qrels. The benchmark covers first-stage retrieval and second-stage reranking, which mirrors an evidence assistant's retrieve-then-rerank workflow.[^t2ranking]

## Experiment ladder

| ID | System | Training | Purpose | Status |
|---|---|---:|---|---|
| E0 | BM25 | No | Lexical baseline | Scaffolded |
| E1 | Pretrained Chinese dual encoder | No | Semantic baseline | Scaffolded |
| E2 | E1 + in-batch contrastive learning | Yes | Establish a transparent PyTorch training loop | Scaffolded |
| E3 | E2 + hard-negative training | Yes | Test whether difficult negatives improve retrieval | Planned |
| E4 | E3 Top-100 + Cross-Encoder reranking | Optional | Test the full two-stage ranking stack | Planned |

No metric is asserted until it is generated by a versioned run. The `artifacts/metrics/` directory is intentionally empty in the first commit.

## Evaluation protocol

The official T2Ranking train/development split is preserved. Training queries, training qrels, and negative files are never used for development evaluation. The test suite checks query overlap, positive/negative collisions, metric behavior, and a CPU-only smoke-training path.

| Metric | Why it is reported |
|---|---|
| nDCG@10 | Primary ranking metric; rewards correct ordering and supports graded relevance. |
| MRR@10 | Captures how quickly the first relevant result appears. |
| Recall@50 / Recall@100 | Tests whether first-stage retrieval passes relevant evidence to later reranking. |
| Latency | Makes quality-versus-cost tradeoffs explicit. |
| Mean ± standard deviation across seeds | Prevents cherry-picking a single favorable run. |

## Quick start

The small `smoke` preset is the only required first run. It creates a compact, deterministic subset from a **locally downloaded** copy of T2Ranking and does not submit data anywhere.

```bash
python -m venv .venv
# macOS/Linux
. .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1

python -m pip install -e ".[dev,train]"

# Place the official T2Ranking files under data/raw/t2ranking/ first.
python scripts/prepare_subset.py \
  --source-dir data/raw/t2ranking/data \
  --output-dir data/processed/smoke \
  --preset smoke \
  --seed 2026

pytest
```

See [data/README.md](data/README.md) for download, license, and file-layout details. See [docs/experiment_protocol.md](docs/experiment_protocol.md) for the complete protocol.

## Reproducibility commitments

Every result must include the exact configuration file, random seed, Git commit, Python/package versions, device information, data-manifest hash, timing information, and output run file. A result without this metadata is treated as exploratory and is not reported as a final experiment result.

## Connection to CountyResearchAI

Only a retriever that demonstrates stable development-set performance and has documented failure cases may be considered for an optional CountyResearchAI adapter. Any future upstream integration must retain the model version, index version, top-k evidence list, and source URLs. Benchmark relevance does not guarantee a generated report is correct; report conclusions still require source and time-scope review.
